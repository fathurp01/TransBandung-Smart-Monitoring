EVALUASI TENGAH SEMESTER 2 – CLOUD COMPUTING
--------------------------------------------------------------------------------

A. Capaian Pembelajaran
Mahasiswa mampu mengetahui dan mengimplementasikan metode keamanan dan rekayasa jaringan menggunakan service cloud computing.
(Note: Soal ini menggunakan AWS sebagai contoh, mahasiswa diperbolehkan menggunakan Huawei Cloud, Google Cloud, Alibaba, atau Azure).

STUDI KASUS
Anda diminta untuk mengembangkan aplikasi berbasis web berbasis cloud yang berfokus pada salah satu domain berikut:

Pilihan Domain:
1. Sistem Transportasi Kota
2. Sistem Pelayanan Publik Desa/Kelurahan

Tentukan Ide Aplikasi:
Pilih salah satu domain, kemudian tentukan ide aplikasi.
Contoh Ide:
- Transportasi: Monitoring transportasi umum (semi real-time), sistem pelaporan kemacetan/kecelakaan berbasis masyarakat, rute dan jadwal.
- Pelayanan Publik: Sistem pengajuan surat (domisili, usaha, dll), pengaduan masyarakat, tracking status layanan administrasi.

Jelaskan:
- Nama Aplikasi
- Deskripsi Singkat
- Target Pengguna (masyarakat, admin, atau keduanya)

KETENTUAN SISTEM (WAJIB)
Aplikasi yang dibuat wajib memenuhi:
- Berjalan di Amazon EC2 (dapat diakses publik)
- Menggunakan Docker dan dijalankan melalui layanan khusus Docker di AWS (WAJIB), seperti: Amazon ECS (Elastic Container Service)
- Menggunakan Amazon RDS (database di private subnet)
- Menggunakan Amazon S3 untuk penyimpanan file
- Menggunakan Amazon CloudFront (CDN) untuk distribusi konten statis
- Menggunakan GitHub Actions untuk CI/CD
- Source code disimpan di GitHub

FITUR MINIMAL APLIKASI
- Minimal 3 fitur utama
- Minimal 1 fitur upload file ke S3 (contoh: upload dokumen, foto laporan, dll)
- Semua data tersimpan di RDS
- Konten statis wajib diakses melalui CloudFront (bukan langsung dari S3)

ARSITEKTUR CLOUD (WAJIB)
Mahasiswa wajib membuat diagram arsitektur sistem dengan komponen berikut:
- VPC
- Public Subnet (ECS, Load Balancer / EC2 jika digunakan)
- Private Subnet (RDS)
- Amazon ECS (menjalankan container Docker)
- Amazon RDS (Private Subnet)
- Amazon S3 (file storage)
- Amazon CloudFront (CDN di depan S3)
- Internet Gateway
- NAT Gateway (opsional, nilai tambah)
- GitHub Actions (CI/CD pipeline ke ECR/ECS)

Ketentuan Arsitektur (Perbedaan dari ETS):
- Aplikasi tidak dijalankan langsung di EC2 manual, tetapi melalui container service (ECS)
- Image Docker harus disimpan di ECR
- Deployment dilakukan melalui pipeline CI/CD ke ECS
- Akses file tidak boleh langsung ke S3, harus melalui CloudFront
- EC2 hanya opsional (misalnya sebagai bastion host), bukan sebagai tempat utama aplikasi

KETENTUAN PENTING
- Aplikasi wajib dapat diakses online saat ETS2 (Senin 4 Mei 2026). Jika tidak dapat diakses -> nilai implementasi = 0.
- Tidak menggunakan CloudFront/S3/ECS/ECR akan mengakibatkan pengurangan nilai signifikan.

LARANGAN PENGGUNAAN AI
Mahasiswa dilarang menggunakan AI (ChatGPT, Copilot, dll) untuk membuat diagram arsitektur.
Jika terbukti menggunakan AI: Nilai = 0.
Tools yang diperbolehkan: draw.io/diagrams.net, Lucidchart, Microsoft Visio, Figma (manual design).

KETENTUAN PENULISAN LAPORAN (WAJIB)
- Setiap gambar atau tabel wajib memiliki pengantar sebelum ditampilkan.
- Setiap gambar atau tabel wajib memiliki penjelasan setelah ditampilkan.
- Tidak diperbolehkan menampilkan gambar/tabel tanpa konteks.
- Penjelasan harus relevan dengan isi gambar/tabel.

OUTPUT YANG DIKUMPULKAN
1. Laporan (PDF) berisi penjelasan sistem dan langkah pengerjaan.
2. Diagram arsitektur (dibuat sendiri, bukan AI).
3. Source code (GitHub link).
4. URL aplikasi (endpoint ECS / Load Balancer / domain).
5. Dockerfile.
6. Workflow GitHub Actions (CI/CD ke ECR/ECS).

DEADLINE
- Pengumpulan hingga 24 April pukul 23.59.
- Kelas AA & BB: Pengumpulan dengan membuat Folder NRP-NAMA-ETS2.

--------------------------------------------------------------------------------
RUBRIK PENILAIAN
--------------------------------------------------------------------------------
1. Deploy Aplikasi (Online) (10%): Berjalan stabil dan publik.
2. Docker + ECS (15%): Menggunakan ECS dengan benar, container optimal.
3. ECR (Docker Registry) (5%): Image tersimpan di ECR dan digunakan dalam deployment.
4. Database (RDS) (10%): Berjalan di private subnet dan terhubung aplikasi.
5. Storage (S3 + Upload) (10%): Upload file ke S3 berjalan baik dan terintegrasi.
6. CDN (CloudFront) (10%): Semua static content diakses via CloudFront.
7. CI/CD (GitHub Actions) (5%): Pipeline otomatis build & deploy ke ECS.
8. Arsitektur Cloud (5%): Semua komponen sesuai (VPC, subnet, ECS, RDS, S3, CDN).
