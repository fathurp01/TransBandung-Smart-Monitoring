3.0.	Prasyarat Wajib Sebelum Setup
Agar proses deployment berjalan lancar dan dapat direplikasi, siapkan kebutuhan minimum berikut sebelum masuk ke tahap 3.1:
•	Akun AWS aktif dengan hak akses untuk VPC, RDS, S3, ECS, ECR, IAM, CloudWatch, dan Secrets Manager 
•	Akun GitHub dengan akses ke repositori TransBandung-Smart-Monitoring 
•	Docker Desktop terpasang dan dapat menjalankan perintah docker compose 
•	AWS CLI terpasang (opsional untuk verifikasi manual) 
•	Domain/subdomain aktif untuk CDN Cloudflare (contoh: cdn.tbsm.com) 
•	Daftar variabel konfigurasi sudah disiapkan: AWS_REGION, nama bucket S3, endpoint RDS, dan domain CDN 

Parameter standar yang direkomendasikan pada proyek ini:
•	Region: ap-southeast-1 
•	Port backend: 8000, port frontend: 80 
•	Branch deployment: main 
•	Nama ECR: tbsm-backend dan tbsm-frontend 
•	Nama ECS Cluster/Service: tbsm-cluster / tbsm-backend-service

3.1.4.	Konfigurasi Workflow CI/CD (GitHub Actions)
Otomatisasi pada proyek ini menggunakan tiga workflow terpisah agar quality gate dan deployment berjalan terstruktur.
•	Workflow 1 (Backend CI): .github/workflows/backend-ci.yml 
•	Trigger: push/pull_request pada perubahan folder backend 
•	Proses: setup Python 3.11 → install dependencies → pytest 
•	Workflow 2 (Frontend CI): .github/workflows/frontend-ci.yml 
•	Trigger: push/pull_request pada perubahan folder frontend 
•	Proses: setup Node.js 20 → npm install → npm run build 
•	Workflow 3 (Deployment): .github/workflows/deploy-ecr-ecs.yml 
•	Trigger: push ke branch main 
•	Proses: login AWS/ECR → build & push image backend+frontend ke ECR (tag SHA dan latest) → render task definition → deploy ke ECS service 
Dengan skema ini, proses CI (uji backend/build frontend) terpisah dari CD (deploy ke AWS), sehingga troubleshooting lebih mudah dan risiko deploy aplikasi rusak dapat ditekan.

3.1.5.	Penyusunan AWS Task Definition (ECS Instruction)
Sebagai pengganti konfigurasi manual di EC2, sistem menggunakan task-definition.json sebagai panduan bagi Amazon ECS untuk menjalankan kontainer.
•	Komponen: Menentukan kebutuhan CPU/RAM, pemetaan port, dan integrasi log ke CloudWatch 
•	Secrets: Mengambil kredensial RDS dan ADMIN_TOKEN dari Secrets Manager (bukan hardcoded), sedangkan domain CDN diset melalui environment variable 
•	Konfigurasi runtime utama: networkMode awsvpc, requiresCompatibilities FARGATE, cpu 256, memory 512 
•	Container utama: backend-container pada port 8000 dengan health check endpoint /api/health 
•	Observability: log driver awslogs ke log group /ecs/tbsm-backend 
•	Catatan implementasi: task definition yang dideploy saat ini berfokus pada service backend; image frontend tetap dibangun dan dipush ke ECR oleh workflow deploy 
Untuk memberikan gambaran konfigurasi yang digunakan oleh ECS dalam menjalankan container, berikut ditampilkan isi file task definition.

3.3 Setup Bagian 2: Rekayasa Jaringan (VPC & Subnet)
Membangun isolasi jaringan virtual untuk memisahkan komponen publik dan privat sesuai standar keamanan SC3.
Langkah-langkah:
•	Buka AWS Console, pilih layanan VPC 
•	Buat VPC baru dengan CIDR block 10.0.0.0/16 
•	Buat 2 Public Subnet untuk Application Load Balancer (ALB) dan ECS Tasks 
•	Buat 2 Private Subnet khusus untuk lokasi Amazon RDS 
•	Pasang Internet Gateway (IGW) dan hubungkan ke VPC 
•	Atur Route Table untuk Subnet Publik agar memiliki rute 0.0.0.0/0 menuju IGW 
•	Siapkan Security Group terpisah: SG-ALB, SG-ECS, dan SG-RDS untuk menerapkan prinsip least privilege 
•	Atur rule minimum: SG-ALB membuka 80/443 dari internet, SG-ECS menerima trafik hanya dari SG-ALB, SG-RDS menerima trafik hanya dari SG-ECS

3.4 Setup Bagian 3: Basis Data Relasional (Amazon RDS)
Menyediakan penyimpanan data yang aman di dalam jaringan privat.

•	Simpan endpoint database untuk digunakan sebagai variabel lingkungan aplikasi 
•	Aktifkan backup otomatis (minimal 7 hari) agar ada mekanisme pemulihan data

3.6 Setup Bagian 5: CDN Terintegrasi (Cloudflare)
Menggantikan Amazon CloudFront dengan Cloudflare untuk distribusi konten statis dari S3.
Catatan: Penggunaan Cloudflare sebagai substitusi CloudFront dilakukan berdasarkan arahan dosen karena kendala penggunaan CloudFront, dan harus dilampirkan buktinya pada bagian lampiran laporan.
Langkah-langkah:
•	Daftarkan domain aplikasi di Cloudflare 
•	Buat rekor DNS tipe CNAME yang mengarah ke endpoint S3 bucket Anda 
•	Aktifkan fitur Proxy (Orange Cloud) pada Cloudflare agar IP asli S3 tersembunyi 
•	Di sisi S3, tambahkan Bucket Policy yang memberikan izin s3:GetObject hanya kepada rentang IP Cloudflare agar keamanan tetap terjaga 
•	Ubah URL akses foto di frontend aplikasi menjadi domain Cloudflare (misal: https://cdn.tbsm.com/file.jpg) 
•	Catatan implementasi: variabel runtime masih bernama CLOUDFRONT_DOMAIN, tetapi nilainya diisi domain Cloudflare/CDN aktif

3.10 Validasi Akhir End-to-End (Wajib Sebelum Pengumpulan)
Bagian ini memastikan deployment tidak hanya sukses di pipeline, tetapi benar-benar berfungsi dari sisi pengguna hingga penyimpanan data.
Checklist validasi:
•	Akses endpoint aplikasi melalui DNS ALB berhasil tanpa error 5xx 
•	Endpoint backend /api/health mengembalikan status sehat 
•	Fitur upload bukti laporan menghasilkan presigned URL dan file masuk ke bucket S3 
•	URL file bukti dapat diakses melalui domain CDN (Cloudflare) yang sudah diproksi 
•	Service ECS berstatus ACTIVE dan task terbaru menggunakan image tag commit terbaru (SHA) 
•	Log CloudWatch tidak menunjukkan error berulang (crash loop/connection refused) 
•	RDS tetap private (Public Access: No) dan koneksi hanya dari SG-ECS 

3.11 Troubleshooting Ringkas
Jika deployment gagal, lakukan pemeriksaan berurutan berikut:
•	GitHub Actions gagal pada login ECR: cek AWS_ACCESS_KEY_ID, AWS_SECRET_ACCESS_KEY, AWS_REGION pada GitHub Secrets 
•	Build image gagal: cek Dockerfile backend/frontend, dependency lock, dan path build context 
•	ECS service tidak stabil: cek CloudWatch Logs dan pastikan environment/secrets wajib (DATABASE_URL, DB_PASSWORD, ADMIN_TOKEN) terbaca benar 
•	Target group ALB unhealthy: cek port container (8000), path health check (/api/health), dan Security Group antar komponen 
•	Upload S3 gagal: cek IAM permission task role, CORS bucket, dan nama bucket pada variabel runtime 
•	File tidak tampil via CDN: cek record DNS Cloudflare, status proxy, serta kebijakan akses bucket S3 

3.12 Checklist Lampiran Bukti Penilaian
Agar laporan siap dinilai tanpa revisi besar, lampirkan bukti minimum berikut:

•	Task definition ECS (containerDefinitions + secrets)

•	S3 Block Public Access + CORS + enkripsi

•	ECR image list (tag latest dan SHA) 
•	ECS Service ACTIVE + target group healthy

•	Bukti persetujuan dosen terkait substitusi CloudFront menjadi Cloudflare
